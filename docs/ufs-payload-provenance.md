# Firmware RAM kernel measurement

The optional `DALI_UFS_MEASURE_PAYLOAD=true` observation runs after the existing
SHA known-answer test and before physical controller initialization. Failure
refuses that controller path. The default remains false for existing RAM and
read-only diagnostic candidates. This switch does not enable media writes.

The builder requires an explicit `DALI_UFS_SOURCE_DEVICE` repository and the
existing `DALI_UNIXNU_PACKAGE` path. It derives device, generic and firmware
revisions from the clean actual Git roots, checks the board's firmware pins,
and obtains the unique fixed XNU feed revision. These form the same 180-byte
compiled record used by the source-only kernel. The PCD input is generated by
the builder; there is no grant/manifest/digest override. The normal packaging
and preflash Mu patch checks still apply. This is local source-input consistency,
not independent compiler or network attestation.

The runtime consumer selects a unique filesystem on the exact firmware RAM
PayloadDxe vendor path, with present, read-only, logical 512-byte BlockIo. It
never opens an arbitrary filesystem by filename or searches physical UFS.
It opens only the original `EFI/UniXNU/Payloads/kernel.macho`, bounds its size
by 128 MiB and the RAM volume, reads its declared length exactly once, checks
EOF and stable file size/media, and closes both file handles before hashing.
Short reads, warnings, failed closes and media changes produce no observation.

The core requires native ARM64 MH_EXECUTE bytes and exactly one well-formed
compiled four-pin record matching firmware's own build metadata. The same marker
may also occur as an ordinary kernel string constant; it is not a source record.
The SHA covers the entire original file, including bytes outside loaded segments.
The source SHA independently reconstructs `DALI-UFS-SOURCE-V1\0` plus canonical
JSON with device/kernel/UEFI/generic/XNU fields, matching the host and XNU consumer.
The resulting digests are observations to compare with an expected grant; they
are never copied from that grant. No partial digest or ready flag escapes failure.

Native tests compile the complete RAM consumer and core with the fixed Mu ABI.
They use an independent Python SHA/JSON backend and hostile filesystem behavior.
Offline replay of an actual earlier Apple kernel is saved separately from physical
qualification. Current runtime grant publication, original-image AVB/zero-scratch
validation, pre-restore evidence export and three UEFI/XNU persistence rounds
remain required. The static firmware write grant is still zero.
